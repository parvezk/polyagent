
PolyAgent helps developers track, understand and approve coding agents across vendors in one place

PolyAgent is the review layer for developers who run several coding agents at once across vendors and across platforms (local, cloud, desktop, mobile, sandbox, CI, browser agent)

On “vendors will build it”: each vendor will build a queue for its own agents. You use four, so the case for PolyAgent is one queue across all of them.

One precision point on your framing: you were not really building a better Jules, because PolyAgent does not write code. You were building the layer that makes Jules replaceable, and that is the stronger claim, because it survives Jules dying. I would use exactly that distinction if a reviewer asks.

“A better Jules across vendors” and the human-in-the-loop idea fit together as one product:

Agents from any vendor work on your repos, and some of them find their own tasks [PRO-ACTIVE SUGGESTIONS].
One queue shows you what’s waiting and what each agent changed, so you can answer, approve or stop it.
